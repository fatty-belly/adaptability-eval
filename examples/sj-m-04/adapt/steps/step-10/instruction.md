Please extend the RAM log handler's `dump_log` API with an opt-in JSON export mode so cached logs can be saved and analyzed offline. When that mode is requested, `dump_log` should return JSON-Lines output, with one JSON object per retained log entry, using the same record data that the structured JSON logging already exposes and also including the cached occurrence count for entries that were collapsed from repeated identical messages. The JSON export needs to respect the same level threshold and log-filter selection as the existing text and HTML dump paths. Unless this JSON mode is explicitly requested, `dump_log` should keep its current behavior so existing callers continue to get the same non-JSON output as before.

Expose the mode as `dump_log(json=True)`. Include `created`, `msecs`, `levelname`, `name`, `module`, `funcName`, `lineno`, `levelno`, `message` and `count`; preserve interpolated messages and optional string tracebacks.
