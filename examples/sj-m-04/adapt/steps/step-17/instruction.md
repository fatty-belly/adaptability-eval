Please make crash reports apply the same redaction to the extra context they include beyond the log itself. In particular, the list of currently open page URLs, the recently visited history URLs, and the command-line arguments should be scrubbed before a report is shown or submitted, using the same masking rules already used for shared diagnostic output. That means passwords embedded in URLs, sensitive URL query-parameter values, inline `Bearer`/`Basic` credentials, and usernames exposed through home-directory paths should no longer be visible in those crash-report fields, while ordinary non-sensitive entries should stay readable and otherwise unchanged.

Preserve normal report entries, grouping and unrelated sections, including the existing choice to exclude logs and extra diagnostic context from a report.
