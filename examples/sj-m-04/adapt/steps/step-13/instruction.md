Please extend the log redaction so shared diagnostic logs also hide sensitive values that appear in URL query parameters. If a logged URL contains query parameters with names such as password/passwd, token/access_token, api_key/apikey, secret, or auth, the parameter values should be masked while keeping the parameter names, the rest of the URL, and any unrelated query parameters readable. Log output without those sensitive query parameters should remain unchanged.

Match the complete query-parameter names `password`, `passwd`, `token`, `access_token`, `api_key`, `apikey`, `secret` and `auth`, not substrings of other names such as `authtoken`, `passwords` or `apikey2`. A sensitive-looking word used as an unrelated parameter's value stays unchanged. Only scan actual URL query parameters: text without a URL scheme and text inside a URL fragment must not be redacted as a sensitive URL query.
